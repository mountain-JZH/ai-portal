# 项目看板 V2.8：当前集成说明

已验收 B/D 布局保持。员工 /projects：综合总览、今日更新、负责人、项目业务；维护 /projects/new 和 /projects/:id/edit；管理员初始化导入 /admin/projects。

唯一入口 /login；旧 /admin/login 重定向。当前不强制首次改密，保留主动修改/管理员重置。管理员一次登录拥有管理与项目维护权限；市场部仅按 can_edit_projects 维护；普通员工只读。权限由服务端检查，不因隐藏按钮而放开接口。

## 数据与 API

- GET /api/projects、GET /api/projects/{id} 读取同一 SQLite；无会话 401，不存在项目 404，非法查询 422。
- POST /api/projects、PATCH /api/projects/{id} 需维护权限及 CSRF，版本冲突 409；历史接口供有效员工只读。
- 数据为空时显示真实空态，不读取私密 HTML、演示数组或 localStorage 公共主数据。
- 管理 API、Excel 匹配及覆盖限制见 [project-dashboard.md](project-dashboard.md)；字段历史、事务及节点编辑见 [project-maintenance.md](project-maintenance.md)。

## 四视角

- overview：项目搜索、业务、负责人、阶段及更多条件，条件限于该视角。
- daily：update_days=1|7|30，含今天的北京时间自然日范围。按最近真实业务修改时间倒序，项目去重，不携带隐藏的综合条件。
- people：组长/负责人切换，并独立记住所选人员。
- business：最多四业务多选 OR，重复项目只显示一次。
- 其他视角可按评级、最新真实修改或名称排序；今日视角固定时间倒序。
- 黄色 KPI 始终只统计今日真实修改项目，创建/初始导入/基线/无变化/仅 AG 变化不算；AG 原文仍在 D 可核对。

## B 卡、节点及持久日期

三栏为项目身份、实际节点/三项文字、业务内容；业务规模不猜测单位，不因多业务突出第一个模块。

- 11 节点精确“已完成”为绿、“进行中”为黄，特殊原文/空白保持；完成数量与当前位置不同。
- 多个黄色节点可不连续，最靠前者优先。没有黄色时显示历史 AC，不从绿色节点推断；只读展示不改写 AC。
- 项目编号右侧只显示一个最新真实业务修改日期：今日为黄色实底，历史为浅黄色日期，同年不带年份、跨年带年份。
- 标签由 latestBusinessUpdateAt 和服务器时间参考按 Asia/Shanghai 格式化，跨日持续显示，不受范围选择影响。
- 节点区域与 AD/AE/AF 不再重复标日期；各字段完整历史、修改人、服务器时间和查看历史入口均保留。

## D 详情与维护

D 使用四章节右侧 dialog，固定头部、单一内容滚动区，保留 Escape、遮罩关闭和焦点恢复。业务原文完整展示。

维护页包含日常进展/完整档案，共用一份草稿、版本和 11 节点编辑器；点击不立即保存。服务端事务记录变化并检查 409。节点附件、历史回滚及第四阶段功能未开发，不应在发布说明中宣称已有。

## 响应式与验证边界

项目容器最大 1620px；桌面约 29/43/28，1200px 紧凑，930px 下业务栏移行，650px 下单栏。当前整合仍使用正式 Header、API 和 SQLite，不嵌入内部原型。

B/D 主要页面已有用户人工验收；新候选仍需现场核验 1440/1280/930/390px、长项目名、跨年长标签、11 节点、历史弹窗及移动端焦点/滚动。自动化、HTTP 和 SSR 不能替代真实视觉验收。
