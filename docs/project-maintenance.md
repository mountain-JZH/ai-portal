# 项目维护与字段历史（第三阶段）

## 维护工作台：日常进展 / 完整档案

编辑页使用共用节点编辑器；B 三栏卡仅调整当前阶段的共享解析，D 四章节只读抽屉、历史组件和看板共享样式保持原样。

- 已有项目 `/projects/:id/edit` 默认“更新项目进展”：只读项目上下文 → 11 节点可点击进度条 → AD / AE / AF → 保存。三个文字字段的历史入口及最近修改信息不变。
- 两个维护模式及新建项目复用 `ProjectNodeEditor.vue`。点击按空白/特殊状态 → 进行中（黄）→ 已完成（绿）→ 空白（灰）循环，仅更新草稿，不推断其他节点；允许不连续的多个进行中节点。窄屏进度条局部横向滚动，保留 44px 触控高度及节点简称、完整名称提示。
- 高级状态编辑默认收起，允许保留或修改原始自由文本。灰色不代表空白；未开始、暂缓、不适用、自定义、空字符串及 NULL 不在加载时归一化。“撤销节点修改”恢复整组原值和原 AC，不撤销其他字段草稿。
- 当前主要阶段按固定顺序选择最早的精确“进行中”。只有节点实际修改并提交时，服务端才在同一事务内同步 AC 并记录历史；仅浏览、提交相同节点或只改其他字段，不改写历史 AC。无进行中节点时保留原 AC 并提示，新项目可无阶段。B 卡显示同一优先级，但不会改写数据库；完成数量只计精确“已完成”。
- “维护项目档案”：基本资料、属性、四类业务、同一进度条。已有内容的业务默认展开，未涉及的折叠；折叠不移除表单数据。光伏保留文本型输入，不猜测单位。已有项目的档案模式不重复显示 AD / AE / AF。
- `/projects/new` 默认完整档案，包含同一节点编辑器及可选初始 AD / AE / AF，一次提交创建，不先保存空项目。
- 模式共用一个响应式表单、一份原始快照和一个版本号。切换模式保留草稿；保存将一并提交两种模式中实际改动的字段，页面明确提示该行为。未保存离开、失败保留、409 不覆盖及无变化不写入保持不变。
- 保存后保持维护页，重新读取服务端内容并显示新版本；返回看板重新获取最新 B 卡，历史窗口通过原接口读取最新日志。新建成功后进入新项目编辑路由的日常模式。

验收地址沿用 `http://127.0.0.1:5175/projects`，后端 8002 仅连接原临时验收库。请使用 market-demo 检查多个/不连续黄色节点、撤销、取消、无黄色保留 AC、特殊状态及保存历史；用 employee-demo 确认只读。桌面和 390px 手机宽度的真实视觉、触控仍需 Edge 人工检查，脚本/SSR 测试不等于浏览器验收。

## 页面与权限

- `/projects` 保留原四视角、B 三栏卡和 D 只读抽屉。
- `/projects/new`、`/projects/:id/edit` 共用完整维护页 `ProjectEditView.vue`。
- 有效员工可读取项目和历史；当前不强制首次改密，保留主动修改与重置；写入另需 `can_edit_projects=true` 或明确管理员身份。
- 统一登录后，管理员自动拥有项目维护权限；市场部等维护人员按 `can_edit_projects` 授权。写接口复用员工会话、CSRF，并在写事务内重新检查权限。
- 三个 B 文字区域、D 抽屉和维护页可打开同一个只读历史窗口。叠加窗口共享背景锁，最后一个窗口关闭才恢复页面。

## 数据与迁移

`project_data.init_project_tables` 调用幂等增量迁移，不重建项目表，不改变永久 ID 或原始 `data`。

新增项目列：`version`（旧记录默认 1）、`created_at`、`created_employee_id`、`updated_at`、`last_edit_source`。

新增 `project_change_logs`：项目 ID、操作批次、字段、完整旧/新值（JSON 标量）、员工不可变 ID、账号/姓名快照、服务器 UTC 时间、修改类型、项目版本、操作来源及可选管理员 ID。按项目/字段、项目/时间、员工/时间建立索引。

旧项目仅为 AD/AE/AF 建立一次初始快照，时间来自实际导入时间，没有时间则明确标注未知；不推测 Excel 产生前的历史。旧项目的真实创建时间和创建人未知，保持 NULL。新建项目记录创建事件和三个文字字段的初始版本，包括空值。

历史无修改/删除 API，员工不能改写历史。改回旧内容仍追加新日志，而非执行版本回滚。

首次启动新版后端将迁移所配置数据库。正式上线前应先备份 SQLite，并在副本演练；本轮自动测试仅迁移临时数据库，未启动新版服务读取真实业务库。

## API

| 操作 | 接口 | 权限 |
| --- | --- | --- |
| 新建 | `POST /api/projects`，直接提交字段对象 | 员工维护权限 + CSRF |
| 更新 | `PATCH /api/projects/{id}`，`{"version":1,"changes":{"situation":"新内容"}}` | 同上 |
| 历史 | `GET /api/projects/{id}/history?field=situation&limit=50&offset=0` | 有效员工 |

可编辑：名称、资源来源、组长、负责人、管理权、所有权、时序/价值评级、客户性质、片区，六个业务原始字段，11 项 `stages`，AC 当前阶段及 AD/AE/AF。项目名称必填；其他允许空值。业务值为原始文本，不猜测储能单位，不把未知量转零。

不接受客户端 ID、操作者、时间、导入批次、AG 标记或系统版本写入业务 JSON。PATCH 只合并实际提交字段。`stages` 提交时须完整 11 项，允许 NULL 和自由文本；日志以 `stage_01` 至 `stage_11` 稳定标识逐节点保存。AC 不自动补全节点。

新增/改名/改来源均检查匹配键冲突，返回 409，不合并项目。

## 事务、并发及导入

- `BEGIN IMMEDIATE` 后验证版本、合并、比较变化、更新当前行并追加日志，一起提交；任何失败一起回滚。
- 一次保存的变更共享 `change_group_id`。无变化不递增版本、不追加日志。
- 旧版本返回 409；维护页保留草稿，用户明确重新加载后才丢弃。保存前确认、未保存离开提醒及请求中防重复提交保留。
- Excel 保留管理员预览/确认流程。快照修订包含新版本，预览后网页改动会使确认失效。
- 保守防护：已有网页维护来源的项目，Excel 不得覆盖其不同内容，预览即阻止，确认再次检查。其他受控导入的实际变化同样递增版本、逐字段追加日志，明确记录执行导入的员工与管理员身份，不推断 Excel 填表人。
- “今日更新”改为读取 `project_change_logs` 的实际业务变化，按北京时间自然日、按项目去重；创建、初始导入、基线、无变化保存及仅 AG 变化不计入。已有项目的受控导入若确实修改业务内容，同样计入，操作来源仍为 `admin_import`。AG 原值保留在数据库和 D 详情中。

## 持久更新日期与时间范围

- `GET /api/projects?view=daily&update_days=1|7|30`：范围包含今天及之前 0/6/29 个北京时间自然日，按项目最新真实业务修改时间倒序；其他视角不混用该范围。黄色 KPI 始终统计今天，不随范围变化。
- 员工列表、详情及保存响应增加 `latestBusinessUpdateAt`、`fieldUpdates`（AD/AE/AF 独立最新时间）、`nodesUpdatedAt`（11 节点实际修改的最新时间）。时间来自日志，不使用整体 `updated_at` 冒充字段时间。不新增表或执行迁移。
- 只读聚合包含 `update/fill/clear/restore`，白名单业务字段和固定节点 ID；排除 `initial/create/baseline`、序号、AG、无实际变化及无有效时区的未知时间。列表一次读取日志投影，与业务数据使用同一只读快照，不逐卡调用历史接口。
- B 卡仅在编号右侧显示项目最新真实业务修改日期：今天为黄色实底“今日更新”，同年往日为浅黄色“M月D日更新”，跨年为“YYYY年M月D日更新”；无真实后续修改不显示。次日保留日期，不受范围筛选影响。节点区及 AD/AE/AF 不重复显示日期；各字段/节点日志、修改人、时间和历史入口完整保留，阶段优先级和完成数不变。
- 页面使用服务端时间参考和 `Asia/Shanghai` 格式化；跨北京时间自然日会刷新统计，日期提示每分钟检查一次。B 三栏、D 只读详情、编辑模式和历史弹窗的业务保持不变。

## 本地人工验收

使用临时数据库与虚构账号，不使用内部原型数据。此前第二阶段无 reload 的验收后端不会自动获得新 API；需在确认后另行启动新版隔离环境。不要把 `DATABASE_PATH` 指向真实 `backend/ai_portal.db`。

1. 普通员工打开看板、D 和三个历史窗口，确认没有编辑入口；直接访问编辑 URL 显示无权限。
2. 获授权员工新建多业务项目，填写未知数值、自由节点状态与长文本。保存后返回看板搜索，核对 B 卡和 D 最新数据。
3. 编辑 AD/AE/AF，核对完整前后文、北京时间、实际账号及同批次。无变化保存不增加日志；清空、再次填写旧值均追加正确日志。
4. 两个员工打开同一版本，先后保存；第二人应收到 409，草稿仍在，不自动覆盖。
5. 1440/1280/930/390px 检查完整表单、三项历史入口、长内容单一区域滚动；从 D 叠加历史，依次关闭，检查 Escape、遮罩、焦点及页面位置恢复。
6. 导入预览后网页修改，再确认应冲突；已有网页维护的项目不能被不同 Excel 内容覆盖。

自动化脚本不等于浏览器视觉验收。真实日志日期统计已实现；第四阶段独立审计后台、附件及版本回滚按钮未实现。生产备份、单次登录账号兼容与回滚以 [部署指南](../DEPLOYMENT.md) 为准。
